# Massachusetts public housing grievance

One interview prepares either an initial grievance or a hearing request after an unresolved informal meeting. It serves current Massachusetts public housing tenants raising their own household's problem. It does not automate voucher disputes, housing applications, appeals of hearing decisions, or eviction court answers. Those limitations appear before users provide personal information.

Entry point: `docassemble.MAGrievanceComplaint:data/questions/lt3grievancecomplaint.yml`.

This release candidate consolidates the complaint and hearing-request workflow in one public entry point. Other historical repositories have not been deleted or archived. The integrated version mentioned in interview-backlog #28 was not found in local checkouts, public branches, or the current user's named/default local and development Playgrounds. This branch therefore extends the existing complaint package.

The output has a handwritten signature line. Users review a PDF, download it, print, sign, and deliver it. Nothing is filed or sent automatically.

## Validation

The three scenarios in `docassemble/MAGrievanceComplaint/data/sources/lt3grievancecomplaint_autogenerated.feature` use only native ALKiln 5 steps. They check the initial letter path, federal hearing path, and appeal guidance, including answer values, resource links, and file downloads.

Run the manual **ALKiln interview tests** GitHub Actions workflow in `.github/workflows/run_form_tests.yml`. It uses the official ALKiln sandbox workflow and a temporary docassemble server; it does not use credentials for a shared server. For other supported methods, use the [official ALKiln setup guide](https://assemblyline.suffolklitlab.org/docs/components/ALKiln/setup/), [writing guide](https://assemblyline.suffolklitlab.org/docs/components/ALKiln/writing/), and [AI interview-testing guide](https://assemblyline.suffolklitlab.org/docs/automated_quality_checks/ai_testing/).

Before release, check the downloaded documents and layout:

- Confirm each letter has the right names, facts, request, and wording for its stage. Check the signing and delivery instructions and the UpToCode and MADE links.
- Edit an answer and download again. Confirm the new answer replaces the old one. Change the request to the appeal path and back; confirm the draft is preserved.
- Check the input, review, and download screens on a narrow phone screen for readable text and usable controls.
- Use a long problem description and check that all text, addresses, and signing lines remain visible in the PDF.

Successful answer-value and download checks alone do not prove the PDF content or layout is correct.

Run local static readiness with the current DAYamlChecker source. Human legal and publication approval must remain separately documented; a clean static scan is not approval.

## Classification

The current LIST snapshot (taxonomy.legal, retrieved November 22, 2026; feed marked June 16, 2026) has no public-housing-grievance-specific term. `HO-03-02-00-00` is the deepest category common to this tool's supported public housing disputes. `CO-04-00-00-00` adds the administrative request/hearing procedure. Narrower public housing terms such as safety, visitors, or admission would falsely imply a narrower or unsupported scope. Do not tag this as general private tenancy, Section 8, or court litigation.

## Review decisions

The old interview categorically excluded anyone involved in listed misconduct, even when the grievance was unrelated. The revision instead explains that some eviction disputes may not qualify and directs the user to their notice, lease, policy, and help. It does not decide grievance eligibility. It also removes the unsupported instruction to wait 30 days and then contact DHCD.

The project owner approved the integrated initial/hearing-request scope, linked MassLegalHelp appeal guidance, current-tenant limits, and non-blocking eviction warning on November 22, 2026. This is a scope decision, not a blanket legal or publication checklist attestation. Appeals are linked to the correct instructions rather than guessing a forum or extending the automated scope.

## Specialized alternatives

The introduction and instructions link [UpToCode](https://uptocode.org/) for repair problems, explicitly explaining that a grievance is not a prerequisite. [MADE](https://www.gbls.org/MADE) is linked for an active eviction court case, including on the grievance-appeal exit; it is not described as a grievance appeal tool. These destinations and their provider descriptions were verified November 22, 2026. MassLegalHelp’s [2025 eviction guide](https://www.masslegalhelp.org/housing-apartments-shelter/eviction/eviction-basics-and-notices-quit) recommends MADE, and its [2025 Protecting Yourself booklet](https://www.masslegalhelp.org/sites/default/files/2025-04/Booklet%201%20Representing%20Yourself%202025.pdf) describes both tools.

## Plain-language pass

The November 22 plain-language pass covers metadata, questions, the letter, and instructions while preserving the examples and scope limits. DAYamlChecker thorough style checking reports no errors or warnings; the remaining informational flags mostly suggest changing the legally correct name “housing authority.” Raw advisory Flesch–Kincaid grades are 5.9 for metadata, 5.8 for screens, and 5.1 for templates. Key legal terms are explained in context. Exact top-4,000 word checks also flag names, inflections, and necessary housing terms; the figures do not certify comprehension. Both letter stages and instructions render on one page in short examples, and a long narrative flows across four pages without losing text.
